# Phase 8 Plan: Presentation Package and Output Levels

<objective>
Implement presentation packaging for existing PartPipeline run outputs. A completed run can be copied into a presentation directory where Level A is the default/recommended segmented-parts artifact from `bridge/prepared_parts.glb`, while Level B is an optional HoloPart comparison artifact from `holopart/output.glb`.
</objective>

<context>
Phase 5 produces `bridge/prepared_parts.glb` and `bridge/part_manifest.json`. Phase 6 can produce `holopart/output.glb`, but the user observed that HoloPart output may be visually messier than the bridge result. Phase 7 added batch manifests and real batch outputs. Phase 8 should package these already-generated artifacts for display without re-running SAMPart3D or HoloPart.
</context>

<truths>

- D-01: Level A is the default and recommended presentation result.
- D-02: Level A source is `bridge/prepared_parts.glb`.
- D-03: Level A should be named clearly, preferably `level_a_segmented_parts.glb`.
- D-04: Level B source is `holopart/output.glb`.
- D-05: Level B is optional comparison/enhancement, not the default display result.
- D-06: Level B is copied only when explicitly requested with an option such as `--include-level-b`.
- D-07: Packaging supports a single completed run directory.
- D-08: Packaging supports a batch manifest.
- D-09: Batch packaging reads items from `batch_manifest.json`.
- D-10: Original GLB copying is optional.
- D-11: The presentation manifest records the original/input path even when the original GLB is not copied.
- D-12: Presentation root is configurable.
- D-13: Default presentation root is `outputs/presentation`.
- D-14: Single-run packages are written under `outputs/presentation/<asset-or-run-name>/`.
- D-15: Batch packaging creates one child directory per item and a batch-level index.
- D-16: Each presentation directory includes `presentation_manifest.json`.
- D-17: The manifest states `default_level: "A"`.
- D-18: The manifest marks Level A as `recommended_for_display`.
- D-19: The manifest includes Level A, optional Level B, optional original GLB, `part_manifest.json`, source run manifest, and recommendation notes.

</truths>

<threat_model>

## Threat Model

- **Accidental expensive model execution:** Presentation commands must only read/copy existing files and write manifests. They must not call SAMPart3D, bridge conversion, or HoloPart.
- **Misleading demo output:** Level A must be marked as recommended and Level B must be labeled optional/comparison so a rough HoloPart result is not shown as the default.
- **Missing artifacts:** If Level A is missing, fail clearly. If Level B or original GLB is explicitly requested but missing, fail clearly instead of silently producing an incomplete package.
- **Large artifact bloat:** Original GLB copying is opt-in; default packages record the source path without duplicating the input.
- **Batch partial failures:** Batch packaging should continue across failed/unusable items and report item-level errors in the batch presentation manifest.

</threat_model>
