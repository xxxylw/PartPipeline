# Phase 7 Plan: Batch, Server Run Mode, and Presentation Outputs

<objective>
Implement a managed batch workflow that stages selected GLBs into PartPipeline-owned input paths, runs the existing SAMPart3D -> bridge -> HoloPart pipeline for a directory of GLBs, writes a batch manifest, preserves per-asset structured outputs, and documents the server-ready run shape for host `d5`.
</objective>

<context>
Phase 4 runs SAMPart3D for one GLB. Phase 5 converts the SAM mask into `bridge/prepared_parts.glb`. Phase 6 runs HoloPart and collects `holopart/output.glb`. Phase 7 should compose these existing stages instead of duplicating model logic. Rich presentation packages and per-part exports are intentionally deferred to Phase 8.
</context>

<threat_model>
## Threat Model

- **Path traversal / accidental overwrite:** Input staging copies files from user-provided directories. Use resolved `Path` objects, copy only files with `.glb` suffix, write into an explicit destination directory, and do not delete source files.
- **Generated artifact leakage into git:** Staged inputs and outputs can be large. Ensure `inputs/` is ignored alongside `outputs/`.
- **Partial batch ambiguity:** Long model runs may fail midway. Write/update `batch_manifest.json` after each asset and include clear per-item `status` and `error` fields.
- **Server credential leakage:** Do not write passwords, private keys, or tokens into docs or manifests. Server docs may mention host alias `d5`, hostname, user, and port only.
</threat_model>

```python
    profile_name: str | None = None,
    output_dir: Path | None = None,
    mask_scale: str | None = None,
    dry_run: bool = False,
    limit: int | None = None,

    run_holopart: bool = True,
    single_run_func=None,
    holopart_func=None,

```

3. Behavior:
   - load config/profile once
   - find top-level `*.glb` files in `input_dir`, sorted by filename
   - apply `limit` after sorting
   - if `input_dir/input_manifest.json` exists, read it and map each staged input path back to its original `source_path`
   - create a batch directory with `batch_manifest.json`
   - for each GLB:
     - call `single_run_func` or `prepare_single_run(...)`
     - if `dry_run=True`, record the single run status and do not call HoloPart
     - if `dry_run=False` and `run_holopart=True`, call `holopart_func` or `run_holopart_for_existing_run(...)`
     - record `asset_name`, `input_path`, `source_path`, `run_dir`, `manifest_path`, `status`, and `error`
     - call `write_batch_manifest(...)` after every item
   - if `continue_on_error=False`, stop on the first item failure after writing the failure to the batch manifest
   - set batch status:
     - `empty` when no GLBs were found
     - `dry_run` when dry-run produced at least one item
     - `complete` when all non-dry-run items completed
     - `partial` when success and failure are mixed
     - `failed` when every attempted non-dry-run item failed
4. Keep existing `prepare_single_run`, `bridge_existing_run`, and `run_holopart_for_existing_run` APIs intact.

</action>
