# Phase 9 Plan: Exploded Assembly Presentation Video

<objective>
Implement exploded-assembly presentation generation for Phase 8 Level A packages. A presentation package should export individual part GLBs and produce a real MP4 where parts start assembled, slide outward from the model center with slight rotation, pause, and return to their original assembled positions.
</objective>

<context>
Phase 8 created `level_a_segmented_parts.glb` as the default presentation artifact. Phase 9 should use that existing GLB and should not rerun SAMPart3D, bridge conversion, or HoloPart. Research found that Blender/ffmpeg are not available in the current WSL PATH, but `trimesh`, `numpy`, `PIL`, `matplotlib`, and `cv2` are available. OpenCV successfully wrote a test MP4 with the `mp4v` codec.
</context>

<truths>

- D-01: The primary deliverable is a real MP4 video.
- D-02: The MP4 is written under an `animation/` subdirectory in the presentation package.
- D-03: The package includes `animation/animation_manifest.json`.
- D-04: Animation starts from the assembled state.
- D-05: Parts move outward from the assembled model center.
- D-06: Parts have slight rotation while moving outward.
- D-07: Animation pauses in the exploded state.
- D-08: Parts move back to original assembled positions.
- D-09: Final frame matches the original Level A arrangement.
- D-10: Use a fixed three-quarter view.
- D-11: Do not add camera orbit in this phase.
- D-12: Frame the model so exploded parts remain visible.
- D-13: Export `parts/part_001.glb`, `parts/part_002.glb`, etc.
- D-14: Part exports are based on Level A, not HoloPart Level B.
- D-15: Part metadata preserves stable order and paths.
- D-16: Batch animation generation is optional.
- D-17: Single-package animation generation is the default path to get right first.
- D-18: Batch does not render videos unless an explicit option is passed.
- D-19: Batch manifests record animation paths when animation generation succeeds.

</truths>

<threat_model>

## Threat Model

- **Expensive accidental rendering:** Batch animation must be opt-in and clearly named.
- **Missing renderer/codec:** The renderer must detect OpenCV `VideoWriter` failure and surface a clear error.
- **Misleading final frame:** The animation must return parts to the original assembled transforms at the end.
- **Part order instability:** Exported part filenames and metadata must be deterministic.
- **Model execution scope creep:** Animation generation must not call SAMPart3D, bridge conversion, or HoloPart.

</threat_model>
